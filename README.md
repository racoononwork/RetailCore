# RetailCore — проектная работа по архитектуре решений

Репозиторий содержит проектную работу по кейсу RetailCore, розничного ретейлера с легаси-платформой обработки заказов. Работа разбита на четыре задания, каждое в своей директории.

## Структура

- Task1 — сбор и анализ требований. Содержит requirements.md, stakeholders.md, interview-scenarios.md и interview-analysis.md.
- Task2 — анализ текущего состояния. Содержит architecture-canvas.md, as-is-analysis.md и исходники диаграмм в diagrams.
- Task3 — целевая архитектура. Содержит transformation.md и исходники диаграмм TO-BE.
- Task4 — планирование миграции. Содержит migration-roadmap.md и cutover-plan.md.

## Диаграммы

Каждая диаграмма существует в двух представлениях. Быстрый вид в Mermaid встроен прямо в markdown-документ, поэтому он рендерится в интерфейсе GitHub без дополнительных шагов. Исходник в PlantUML лежит рядом в директории diagrams соответствующего задания, а из него генерируются картинки PNG и SVG.

### Как генерируются картинки

Картинки создаются автоматически двумя способами. Локально это делает pre-commit hook перед каждым коммитом. В CI это делает GitHub Actions при push с изменением файлов *.puml, после чего результат коммитится обратно в ветку.

Локальная установка pre-commit выполняется так.

```bash
pip install pre-commit
pre-commit install
```

Ручной запуск рендера без коммита выполняется так.

```bash
scripts/render-diagrams.sh
```

Скрипт ищет PlantUML в таком порядке: команда plantuml, Docker-образ plantuml/plantuml, либо jar по пути из переменной окружения PLANTUML_JAR. Для локального рендера нужен один из этих вариантов, а также Graphviz для части диаграмм.

## Обозначения в документах

Статус утверждений обозначается словами. Значение «Подтверждено» означает прямое подтверждение в кейсе или интервью. Значение «Гипотеза» означает косвенный вывод, требующий проверки. Значение «Пробел» означает, что значение во входных данных отсутствует и его нужно уточнять у названного стейкхолдера.
